# Audience and Argument Guide

Read this reference when the audience is skeptical, mixed, unfamiliar with the domain, or expected to make a consequential decision.

## Audience Brief

Capture only information that changes communication choices:

| Dimension | What to determine | Narrative consequence |
| --- | --- | --- |
| Identity and role | What responsibility and authority do they have? | Frame stakes and call to action at their altitude. |
| Decision | What must they approve, choose, understand, or do? | Remove material that does not support that decision. |
| Prior knowledge | Which concepts can be assumed? | Set vocabulary and explanation depth. |
| Incentives and concerns | What creates value or risk for them? | Choose the opening, examples, and tradeoffs. |
| Skepticism | Which claim will they challenge first? | Put the strongest relevant evidence near that claim. |
| Evidence threshold | Do they trust demos, metrics, mechanisms, references, or operational proof? | Select proof type and granularity. |
| Attention and format | How much time and interaction are available? | Choose progressive depth and sequence. |

## Governing Thought

Write one sentence containing:

```text
Because [audience-relevant situation or evidence],
we should understand or do [main point],
so that [decision-relevant consequence].
```

This is a reasoning constraint, not mandatory final wording.

## Communication Job

Choose the primary job before choosing a structure:

- Learning: build capability through a guided path and feedback.
- Action: help an already situated user accomplish a task.
- Reference: make authoritative facts easy to retrieve.
- Explanation: connect causes, concepts, and context into understanding.
- Review: enable scrutiny against explicit criteria and evidence.
- Decision: compare consequences and enable a commitment.

If several jobs are necessary, layer or separate them. A reference appendix should not interrupt a five-minute decision argument, and a decision pitch should not masquerade as a tutorial.

## Argument Shapes

Choose the shape that matches the communication job:

- Decision: situation → complication → options → evaluation → recommendation → ask.
- Explanation: familiar context → surprising behavior → mechanism → consequences → limits.
- Proposal: unmet outcome → root cause → approach → proof → adoption path → commitment.
- Demonstration: user job → before state → critical interaction → after state → operational caveat.
- Technical handoff: system purpose → critical scenarios → responsibilities/contracts → risks → next change.

## Translation Without Distortion

- Replace jargon with consequences or mechanisms, not vague positive adjectives.
- Preserve direction of causality: do not say a feature causes an outcome when evidence only shows correlation.
- Preserve scale and frequency: an edge case should not become the normal story, or vice versa.
- Preserve uncertainty status: plans, prototypes, measured results, and production behavior need different language.
- Explain a technical boundary by what it owns and promises, not only by analogy.

## Objection Handling

For each high-priority objection, record:

```text
Audience concern:
Why it is reasonable:
Answer:
Evidence:
Remaining uncertainty:
Decision implication:
```

Do not manufacture objections merely to rebut weak versions of them.

## Mixed Audiences

If two audiences have different decisions or evidence thresholds, use a layered package:

1. shared governing point and stakes;
2. audience-specific path or appendix;
3. explicit handoff between strategic, operational, and technical detail.

If the governing points differ, create separate narratives.
