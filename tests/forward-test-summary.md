# Forward Test Summary

The four incubating skills were exercised by an independent agent against synthetic but operationally realistic evidence bundles. The test checked whether each skill changed the analysis in the intended way; it did not compare exact headings or wording.

## `software-system-mastery`

Scenario: prepare a new owner to change cancellation in an order, inventory, payment, and fulfillment system with synchronous reservation, asynchronous payment, at-least-once events, manual replay, and no unified trace.

Observed behavior:

- Treated the result as a provisional mental model because no code or runtime evidence was available.
- Traced cancellation across race windows, state ownership, compensation, replay, idempotency, and observability.
- Distinguished reported facts, inferences, proposed invariants, and unsafe assumptions.
- Ended with an evidence-acquisition order and a teach-back/impact-prediction gate rather than claiming mastery from document length.
- Did not produce a paper-style repo wiki or enumerate imaginary files.

Result: passes the intended boundary and evidence discipline.

## `requirements-reality-check`

Scenario: assess a promise to display every forklift across 30 warehouses with one-meter accuracy and one-second latency in three months, despite incomplete Wi-Fi, old Android devices, no UWB, two WMS versions, offline night shifts, and no 24/7 support.

Observed behavior:

- Separated the likely management need from the proposed dashboard and absolute technical claims.
- Identified direct contradictions rather than treating every gap as a question.
- Exercised normal, peak, degraded, recovery, maintenance, device, integration, and ownership scenarios.
- Proposed evidence-buying experiments whose outcomes would change the decision.
- Returned `discovery required`, a reframed pilot requirement, verification and validation conditions, and explicit non-commitments.

Result: passes; it resisted turning an unsupported request into a polished specification.

## `project-narrative-builder`

Scenario: build a five-minute decision narrative for a hospital information leader from a two-fridge, 14-day cold-chain prototype with three temperature events, four-minute average alert latency, and unvalidated identity, network recovery, and clinical outcomes.

Observed behavior:

- Defined the audience's actual decision as approving a bounded eight-week pilot, not purchasing hospital-wide deployment.
- Kept verified facts separate from inferences and prohibited extrapolations.
- Built the argument around decision evidence, strongest objections, trial exit conditions, and next action.
- Adapted evidence and vocabulary to the audience without claiming clinical or production proof.
- Produced a narrative blueprint and sample briefing while leaving visual slide rendering to another skill.

Result: passes the audience/action boundary and truth-preservation checks.

## `architecture-drift-audit`

Scenario: compare ADR-007, which makes Billing the sole writer of financial state, with an Order reconciliation job that directly updates the Billing database and is supported by deployment credentials and six integration tests.

Observed behavior:

- Preserved ADR intent and historical context while refusing to treat a temporary comment as accepted evolution.
- Classified the cross-database write as high-severity divergence without claiming unproven data corruption.
- Connected code, credentials, tests, documentation, auditability, ownership, and future change cost.
- Recommended staged evidence gathering, contract recovery, test migration, controlled cutover, permission removal, ADR treatment, and focused fitness functions.
- Exposed ambiguity when `Divergence` and `Unplanned` could both describe one relationship.

Correction made: the drift model now requires one primary classification and defines precedence; confidence and unresolved consequences remain separate qualifiers.

Result: passes after the classification-priority correction.

## Remaining Validation

These tests validate instruction behavior on bounded evidence, not automatic selection inside a large installed skill set. The skills remain marked as incubating and should be invoked by absolute path in real tasks. Real-use failures should lead to narrow corrections rather than broader catch-all rules.
